# Обязательный набор тестов Block 22

Документ фиксирует, как проверяется требование «не только unit-тесты»:

- интеграционные сценарии выполняются на **реальной PostgreSQL**;
- конкуренция проверяется **действительно параллельными** HTTP/сервисными
  вызовами на разных соединениях, а не последовательными вызовами;
- миграции прогоняются на одноразовом PostgreSQL через Testcontainers;
- контракт фронтенда и бэкенда проверяется отдельно, включая E2E-цепочки.

Все классы набора находятся в
`helpTree-service/src/test/java/org/example/helptreeservice/block22/`.

## 1. Как запускать

Предварительно должны быть доступны:

- PostgreSQL с базой `helpTree_db` (пользователь `helpTree` / пароль `helpTree`);
- Docker — только для `Block22MigrationTest` (образ `postgres:16`).

```powershell
# Интеграционные тесты против локальной БД
$env:INTEGRATION_TEST = 'true'
.\mvnw.cmd -B -pl helpTree-service test
```

Поднимите PostgreSQL на `localhost:5432` с базой `helpTree_db` и учётными
данными `helpTree` / `helpTree` перед запуском. Без `INTEGRATION_TEST=true`
интеграционные классы пропускаются.

Фронтенд:

```powershell
Set-Location frontend
npm ci
$env:CI = 'true'
npm test -- --watchAll=false
npm run build
```

Тестовый профиль (`src/test/resources/application.yaml`) отключает rate limiting
и login-protection, чтобы тесты не упирались в общий счётчик. Сценарий
rate-limit в `Block22ReportIntegrationTest` создаёт собственную включённую
конфигурацию и реальный `DistributedRateLimiter`.

## 2. Изоляция и очистка

`Block22TestSupport` — общая база для всех интеграционных классов:

- пользователи создаются в обособленном пространстве
  `b22-<uuid>@test.local`;
- `@AfterEach` удаляет все строки набора в порядке внешних ключей
  (отчёты и их события, чаты и сообщения, отзывы, помощи, комментарии, кошелёк,
  сессии, блокировки и самих пользователей);
- ни один тест не оборачивается в `@Transactional`: коммиты должны быть
  настоящими, иначе после-коммитные эффекты (кэш, уведомления, outbox) и
  параллельные транзакции не проверяются;
- `runConcurrently` / `runConcurrentlyAllowFailure` поднимают пул потоков,
  синхронизируют старт через `CountDownLatch` и возвращают проигравших гонку
  как доменные исключения, чтобы можно было отличить ожидаемый конфликт от
  серверной ошибки.

## 3. Матрица покрытия

### 22.1 Безопасность — `Block22SecurityIntegrationTest` (9 тестов)

| Сценарий | Проверка |
| --- | --- |
| Выход из одной сессии | `logout` отзывает только текущую сессию; вторая сессия продолжает работать |
| `logoutAll` | Инвалидирует все access/refresh-токены, поднимая `tokenVersion` |
| Заблокированный пользователь | JWT-фильтр отдаёт 403 `ACCOUNT_BLOCKED`, валидатор сессии — `AccountBlockedException` |
| Удалённый пользователь | И фильтр, и валидатор отклоняют токен (401 / `UnauthorizedException`) |
| Устаревшая роль | Смена роли в БД лишает старый токен прежних прав |
| Чужой WebSocket-чат | SUBSCRIBE/SEND в чужой чат отклоняются |
| Чужой HTTP-чат | Чтение и изменение чужого чата запрещены |
| Telegram ID и избранное | Доступ только владельцу или ADMIN |
| Чужие ресурсы | `AuthorizationService` с реальными атрибутами запроса не даёт управлять чужими объектами |

### 22.2 Помощь — `Block22HelpIntegrationTest` (7 тестов)

| Сценарий | Проверка |
| --- | --- |
| Долг получателя | При `debt > threshold` и `helped < debt` приём помощи запрещён |
| Блокировки | Заблокированный helper/получатель не могут принять помощь; блок `HELP_REQUESTS` запрещает приём |
| Подтверждение заблокированным | Заблокированный получатель не может подтвердить помощь |
| Конкурентный accept (6 потоков) | Ровно один `ACCEPTED`, остальные — `ConflictException`; в БД одна активная помощь |
| Конкурентный confirm (4 потока) | Награда начисляется ровно один раз, все ответы `CONFIRMED` |
| Роли | Получатель не завершает помощь, helper не подтверждает |
| Завершение/отмена | Завершённую помощь нельзя отменить, подтверждение — единственная точка награды |

### 22.3 Кошелёк — `Block22WalletIntegrationTest` (7 тестов)

| Сценарий | Проверка |
| --- | --- |
| VIP | Цена берётся с сервера (`economyConfig`), а не из запроса клиента |
| Конкурентные кредиты и дебеты (12 потоков) | Ни одна операция не теряется, баланс не уходит в минус, ledger равен фактическому балансу, reconciliation не находит расхождений |
| Недостаток средств | Дебет не может сделать баланс отрицательным |
| Одна награда на действие | Повтор действия не начисляет второй раз |
| Boost при закрытом посте | Отказ без списания |
| Сбой boost | Транзакция откатывает списание |
| Успешный boost | Один дебет, `boostedUntil` сдвинут, повтор идемпотентен |

### 22.4 Чат — `Block22ChatIntegrationTest` (7 тестов)

| Сценарий | Проверка |
| --- | --- |
| Удаление сообщения через чужой URL | Чужой чат → `ForbiddenException`; неверный `chatId` → `NotFoundException` |
| Удаление сообщения | Только отправитель; чужое сообщение удалить нельзя |
| Конкурентное создание чата (6 потоков) | В БД ровно один чат на нормализованную пару, все получают один `ChatResponse` |
| Приватное удаление чата | Скрывается только у вызвавшего; новое сообщение восстанавливает чат для обоих |
| Непрочитанное и `lastReadMessageId` | Счётчик и курсор соответствуют активным сообщениям |
| Блок `MESSAGES` | Запрещает новые сообщения в паре и не мешает общаться с третьими лицами |
| Чужие события | Подписка/отправка в чужой чат не создаёт событий |

### 22.5 Отзывы и рейтинг — `Block22ReviewIntegrationTest` (8 тестов)

| Сценарий | Проверка |
| --- | --- |
| Права | Отзыв только участником подтверждённой помощи |
| Уникальность | Второй отзыв на ту же помощь запрещён даже после soft-delete |
| Бонус | Начисляется ровно один раз, ledger сходится с балансом |
| Создание/удаление | Рейтинг 3.1 → 3.3 → 3.1, кэш `userRating` инвалидируется |
| Редактирование | Пересчёт по формуле `3.1 - (2.0 * 0.5 * 0.2)` |
| Ответ и удаление | Ответ только получателю, удаление только автору |
| Административное удаление | Нужны ADMIN и причина; пишется `REVIEW_DELETED` в `admin_audit_log` |
| Топ рейтинга | Не содержит `null` и удалённых пользователей |

### 22.6 Комментарии — `Block22CommentIntegrationTest` (8 тестов)

| Сценарий | Проверка |
| --- | --- |
| Удалённый пользователь | Не может комментировать (`NotFoundException`) |
| Заблокированный пользователь | Не может комментировать (`AccountBlockedException`) |
| Полный блок автора поста | Комментарии закрыты |
| Родитель из другого поста | `BadRequestException` |
| Удаление через чужой `postId` | `NotFoundException` |
| Права удаления | Только автор или ADMIN |
| Soft-delete | Дерево и ответы остаются видимыми, счётчик уменьшается |
| Повторное удаление | Счётчик комментариев поста не уходит ниже нуля |

### 22.7 Жалобы и модерация — `Block22ReportIntegrationTest` (9 тестов)

| Сценарий | Проверка |
| --- | --- |
| Создание и чтение | Пользователь видит только свои жалобы |
| Закрытый объект | Повторная жалоба на закрытый объект отклоняется, на открытый — разрешена |
| Дубликаты | Открытый дубликат — `ConflictException`; после решения можно пожаловаться снова |
| Идемпотентность | Повторный ключ возвращает сохранённую жалобу |
| Внутренние заметки | Видны только в admin-представлении, в публичной истории отсутствуют |
| Статус и история | Действие модератора пишет историю; закрытая жалоба неизменяема |
| Права ADMIN | Только ADMIN работает с очередью и действиями |
| Заблокированный/удалённый автор | Не может создать жалобу |
| Rate limit | Третий write в окне получает 429 из общего хранилища, `verify(chain, times(2))` |

### 22.8 Миграции — `Block22MigrationTest` (6 тестов, Testcontainers)

| Сценарий | Проверка |
| --- | --- |
| Чистая PostgreSQL | Flyway прогоняет V1–V62 без ошибок |
| Данные V40 | Загружается `scripts/fixtures/legacy_v40_data.sql`, затем миграции до последней версии |
| Сохранность данных | Пользователи, посты, помощи и кошелёк сохраняются; рейтинг 0 → 3.0, `NULL debt` → 0 |
| Проекции | Появляются строки `user_rating_stats`, ожидаемые для legacy-данных |
| Уникальность и ограничения | Уникальные индексы действительно уникальны; ограничения отвергают некорректные данные |
| Партиционирование | `messages` и `outbox_events` созданы как partitioned-таблицы (`pg_inherits`, `relkind = 'p'`) |

Класс помечен `@Testcontainers(disabledWithoutDocker = true)`: без Docker он
пропускается, а не падает.

### 22.9 Контракт и E2E

`Block22ContractTest` (8 unit-тестов, без БД):

- поля `PageResponse` и отдельный конверт `CommentPageResponse`;
- `HelpResponse.status` — стабильная строка;
- `ReportResponse` не содержит `internalNote`, admin-DTO содержит;
- `ChatResponse.unreadCount` — число;
- DTO кошелька и boost отдают серверные значения;
- `ErrorResponse` содержит `status/code/message/traceId/fieldErrors`;
- `ApiErrorWriter` формирует тот же конверт из фильтров, что и MVC.

`Block22EndToEndIntegrationTest` (4 сценария):

| Цепочка | Что доказывается |
| --- | --- |
| Жалоба → модерация → уведомление | Статус `REJECTED`, уведомление автору, внутренние заметки не утекают |
| Блок → чат | Сообщение после `MESSAGES`-блока отклонено, после разблокировки проходит |
| Помощь → завершение → подтверждение → награда | Награда только при подтверждении, повтор не даёт вторую |
| Boost → списание → изменение поста | Цена совпадает со списанием, ledger сходится, повтор идемпотентен |
